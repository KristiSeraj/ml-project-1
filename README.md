## From a fresh clone

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python data/get_data.py          # fills data/raw/
jupyter lab                      # then run the notebooks in order
```

Nothing under `data/`, `models/` or `reports/figures/` is committed: all of it
is either external input or regenerated by the code here.

## Layout

| Where | What goes there |
|---|---|
| `data/raw/` | Original files. Read-only, never edited, never committed. |
| `data/processed/` | Derived tables. Generated by code, so disposable. |
| `data/get_data.py` | The download. Idempotent. |
| `notebooks/` | Thinking, in order. Narrative, plots, decisions. |
| `src/` | Any function used more than once. Notebooks import from here. |
| `models/` | Trained models and encoders. Output, not source. |
| `reports/figures/` | Figures for the report, findable when writing up. |
| `reports/report.md` | The write-up. |
| `PROBLEM.md` | The problem card, written first, kept up to date. |
| `MODEL_CARD.md` | The model card, written last. |

## The notebooks

| Notebook | What it settles |
|---|---|
| `01-frame.ipynb` | The question, the target and its decisions, the baseline ladder. |
| `02-clean-and-split.ipynb` | The audit, the cleaning decisions, the split, and the analysis. |
| `03-features.ipynb` | The features, the pipeline, and what each addition did on June. |
| `04-evaluate.ipynb` | The chosen model, the slices, the decision, and the one look at July. |

July is held back and looked at once, in `04`.

## Rules this repo keeps

- A function used twice moves to `src/`; a notebook never holds shared code.
- Cleaning lives in `src.data.clean`, so the audit and the training table cannot drift.
- The preprocessor is fitted on the training split only.
- The metric and the ship threshold are named in `PROBLEM.md` before any modelling.

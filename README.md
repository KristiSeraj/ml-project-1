# ml-project-1 — How long will this trip take?

Team B. A passenger has just got into a New York yellow taxi; this repository
builds the model that tells them when they will arrive. Regression, predicted
at pickup, target is minutes from pickup to drop-off. Data is the TLC's
published trip records: 200,000 trips from each of May, June and July 2026,
raw on purpose.

- The question, the target and every decision inside it: [PROBLEM.md](PROBLEM.md)
- What was built, what it scores and where it fails: [MODEL_CARD.md](MODEL_CARD.md) *(week 4)*
- The write-up: [reports/report.md](reports/report.md)

## From a fresh clone

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python data/get_data.py
jupyter lab
```

`data/get_data.py` downloads the four files into `data/raw/` and unpacks the
zone shapefile. It skips anything already there, so it is safe to re-run.
Then run the notebooks in order.

Nothing under `data/`, `models/` or `reports/figures/` is committed: all of it
is either external input or regenerated by the code here.

## The data

| File | What it holds |
|---|---|
| `yellow_tripdata_2026_sample.parquet` | 600,000 trips, one row each, all 21 original columns |
| `taxi_zone_lookup.csv` | Name and borough of each of the 265 zone numbers |
| `taxi_zones/` | Zone boundaries, for maps (coordinates in **feet**, not lat/lon) |
| `data_dictionary_trip_records_yellow.pdf` | The official meaning of every column and code |

The split is fixed so results compare across teams: **May trains, June decides
everything, July is scored once.**

## The site

A static page that runs the model in the browser — no backend, no build step:

```bash
python site/export.py                  # refit on May, write the page's JSON
node site/parity.js                    # browser predictions vs scikit-learn
python -m http.server -d site 8000     # then open http://localhost:8000
```

The decision tree and the preprocessor's fitted numbers are exported to
`site/model.json`; `site/model.js` rebuilds the feature vector and walks the
tree in about 40 lines. Because an app has no measured distance at pickup,
the page estimates the route from the zone shapefile — centre to centre,
times a detour factor of 1.27 learned on May — and says so on the page.
`site/README.md` has the detail; `.github/workflows/pages.yml` deploys it to
GitHub Pages on a manual trigger, and refuses to deploy if parity fails.

## The code

| Module | What lives there |
|---|---|
| `src/data.py` | Loading, the zone join, `duration_min`, the validity and population rules, the findings table, `rebuild()`, the split. |
| `src/features.py` | The allow-list of columns knowable at pickup, the leakage guard, the derived features, the shared preprocessor. |
| `src/models.py` | The ladder as estimators (`MedianDuration`, `TypicalSpeed`, depth-2 tree), linear regression, the decision tree, saving. |
| `src/evaluate.py` | MAE/RMSE, slice tables with counts, the buffer, the bootstrap interval, figures. |

`src.data.rebuild()` goes from the published raw files to the table a model
trains on in one call, so everything is reproducible from a fresh clone.

## Rules this repo keeps

- **Nothing settled at the end of the trip is a feature.** The meter charges
  for time, so `fare_amount` contains the answer; so do `total_amount`, every
  fee, `payment_type` and `RatecodeID`.
- `trip_distance` is **assumed** to stand for the planned route's length. It
  was measured during the trip, so it flatters every score here. Said out loud
  in `PROBLEM.md`, in `01-frame.ipynb`, and in the model card.
- Cleaning lives in `src/`, so the audit and the training table cannot drift.
- Every learned step is fitted on May only, inside a pipeline.
- The metric and the ship threshold are named in `PROBLEM.md` before any modelling.
- A function used twice moves to `src/`; a notebook never holds shared code.

## Declaration of AI use

Claude (Anthropic's Claude Code) was used throughout this project. Where:

- **Repository scaffolding** — the directory layout, `.gitignore`,
  `requirements.txt`, and the module and notebook skeletons.
- **`PROBLEM.md`** — drafted with the model, including the validity rules and
  the population decisions (flex fare trips, voided trips, unknown zones,
  negative amounts, non-standard rate codes). The decisions are the team's to
  defend.
- **`src/`** — all four modules were written with the model: the cleaning
  rules and findings table in `data.py`, the leakage guard and preprocessor
  in `features.py`, the ladder estimators in `models.py`, and the metrics,
  slice tables, buffer and bootstrap in `evaluate.py`.
- **`notebooks/01`–`04`** — structure, code and analysis cells were written
  with the model; the conclusions written in prose are the team's.
- **`MODEL_CARD.md`, `README.md`, `reports/report.md`** — drafted with the
  model from the numbers the notebooks produce.
- **`site/`** — the whole static site (page, stylesheet, browser model,
  exporter, parity check) was written with the model.
- **`data/get_data.py`** — supplied by the course, unmodified.

No other AI tool was used. Every number in this repository is produced by the
code in it and can be reproduced from a fresh clone.

# ml-project-1 — How long will this trip take?

Team B. A passenger has just got into a New York yellow taxi; this repository
builds the model that tells them when they will arrive. Regression, predicted
at pickup, target is minutes from pickup to drop-off. Data is the TLC's
published trip records: 200,000 trips from each of May, June and July 2026,
raw on purpose.

- The question, the target and every decision inside it: [PROBLEM.md](PROBLEM.md)
- What was built, what it scores and where it fails: [MODEL_CARD.md](MODEL_CARD.md) *(week 4)*
- The write-up: [reports/report.md](reports/report.md)

## From a fresh clone

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python data/get_data.py
jupyter lab
```

`data/get_data.py` downloads the four files into `data/raw/` and unpacks the
zone shapefile. It skips anything already there, so it is safe to re-run.
Then run the notebooks in order.

Nothing under `data/`, `models/` or `reports/figures/` is committed: all of it
is either external input or regenerated by the code here.

## The data

| File | What it holds |
|---|---|
| `yellow_tripdata_2026_sample.parquet` | 600,000 trips, one row each, all 21 original columns |
| `taxi_zone_lookup.csv` | Name and borough of each of the 265 zone numbers |
| `taxi_zones/` | Zone boundaries, for maps (coordinates in **feet**, not lat/lon) |
| `data_dictionary_trip_records_yellow.pdf` | The official meaning of every column and code |

The split is fixed so results compare across teams: **May trains, June decides
everything, July is scored once.**

## Rules this repo keeps

- **Nothing settled at the end of the trip is a feature.** The meter charges
  for time, so `fare_amount` contains the answer; so do `total_amount`, every
  fee, `payment_type` and `RatecodeID`.
- `trip_distance` is **assumed** to stand for the planned route's length. It
  was measured during the trip, so it flatters every score here. Said out loud
  in `PROBLEM.md`, in `01-frame.ipynb`, and in the model card.
- Cleaning lives in `src/`, so the audit and the training table cannot drift.
- Every learned step is fitted on May only, inside a pipeline.
- The metric and the ship threshold are named in `PROBLEM.md` before any modelling.
- A function used twice moves to `src/`; a notebook never holds shared code.
